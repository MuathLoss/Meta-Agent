# Workspace continuation — September 10, 2026

This continues the May 22 Smart Import work and the September startup investigation. Public hosting remains deferred by request.

## What changed

- Portable startup uses the environment's Python directly and does not depend on an old activation path. `setup_local.sh` refreshes environment paths and installs the declared dependencies, including XLSX support. The runner checks startup health, avoids occupied ports, and stops only the processes it started. It never seeds or resets the database.
- Telegram errors are isolated per channel, credentials are not printed, and rejected tokens use a five-minute retry delay. Replacing a token makes it eligible again immediately. Existing webhooks are preserved.
- A quieter charcoal/maroon workspace, simpler sign-in, role-aware navigation, a useful overview, and a setup guide linked to real saved configuration. Knowledge wording and channel setup are simpler; advanced settings are tucked away. Desktop/mobile visual verification remains blocked by the browser tool's enforced-policy availability check; build and API checks pass.
- Channels show required-field status and explicit connection checks. Updating one field preserves other saved credentials. Virtual replies remain separate from actual provider delivery. Live sending requires an explicit saved setting.
- Smart Import supports encrypted, redacted review drafts; revision checks; resume; recent history; idempotent approval; and transactional batch undo. Undo refuses all changes if imported content was subsequently edited, removed, or used by another topic. Existing answers are preserved. Handoff changes are saved only when explicitly selected; protected topics retain immediate handoff.
- Optional local Ollama grouping assigns review groups only. It never approves content, creates answers, or changes routing. Topic grouping works when local AI is disabled or unavailable. AI grouping is limited to 80 messages, and import reviews to 500 messages / 2 MB.
- Internal deployment, UAT, and handoff tools require a platform administrator on the server and are hidden from customer navigation. Platform support access asks for an audit reason.
- Local staging has isolated storage, migration ordering, health checks, rotating logs, backup and restore verification, and an HTTPS template for later hosting.

## Continuing locally

```sh
bash setup_local.sh
backend/.venv/bin/python scripts/upgrade_local.py --apply
bash start_all.sh
```

Open `http://127.0.0.1:5173`. Use `bash stop_all.sh` to stop project services. Use `bash start_all.sh --without-telegram` for interface work without provider polling. The database upgrade helper accepts only the known previous schema or the new schema, creates a private database/configuration/upload backup first, and verifies unchanged existing row counts afterward.
